# Codex SuperBullet Global Mode Design

## Goal

Provide a portable, user-level Codex mode named **SuperBullet** that is enabled
by default for substantive work across projects, while keeping its execution
and validation responsibilities explicit and truthful.

## Requirements

- Install a user-level `AGENTS.md` below `${CODEX_HOME:-$HOME/.codex}` so
  conversations in different project paths receive the same policy.
- Keep the mode enabled by default; the user can disable it for the current
  turn or conversation with `关闭 SuperBullet` (or an equivalent explicit
  disable request), and can re-enable it with `开启 SuperBullet`.
- Use Luna at maximum reasoning for execution, decomposition, and any actual
  delegation. Do not claim delegation unless it occurred.
- Use Sol at high or maximum reasoning only for read-only validation. Sol must
  not edit files, fix findings, spawn work, browse broadly, or expand scope.
- Print a truthful marker only when the mode is actually being used:
  `SuperBullet: active — Luna execution` and/or
  `SuperBullet: active — Sol validation`.
- Ordinary explanations, simple questions, and read-only checks must not claim
  SuperBullet activity merely because the default policy exists.
- Provide a `super-bullet` launcher with `run`, `exec`, and `review` commands:
  - `run` starts an interactive Luna session using the profile.
  - `exec` runs a noninteractive Luna task and then invokes a Sol read-only
    review when execution succeeds.
  - `review` invokes only the Sol read-only review.
- Reuse the existing Codex provider and authentication by layering a profile;
  never copy credentials into the profile, launcher, or repository.
- Make installation idempotent and preserve any pre-existing user AGENTS file
  or runtime file with a state backup before replacing it.

## Architecture

The repository owns public templates under a new isolated
`modules/codex-super-bullet` module. The installer copies those templates to
the target user's Codex home and `~/.local/bin`, resolving all paths from
`$HOME`/`$CODEX_HOME` rather than a hard-coded username. The profile contains
only the Luna model, maximum reasoning, and the verified `multi_agent` feature;
the base `config.toml` supplies the existing provider and stored auth.

The global AGENTS policy is the behavioral contract for interactive sessions.
The launcher provides deterministic command-line entry points and prints phase
markers only immediately before a phase that is actually invoked. The launcher
returns a non-zero status if execution fails or if the follow-up review fails.

## Safety and boundaries

- No secrets, auth files, SSH keys, cookies, or provider URLs with credentials
  are copied into Git or generated by the installer.
- The installer performs user-level writes only; it does not call `sudo`.
- Sol review is read-only by using `codex review`, explicit Sol/high overrides,
  and disabled multi-agent behavior. Findings are reported, never auto-fixed.
- Existing unrelated repository changes remain untouched.

## Verification

Tests will cover template contents, profile settings, launcher dispatch and
phase ordering, truthful marker requirements, secret exclusion, idempotent
installation into a temporary home, shell syntax, and the full existing test
suite. A live Codex request is not required for the repository test suite;
runtime installation will additionally parse the profile with the installed
Codex CLI and verify launcher help.
